# 인증 화면 설계 (로그인 · 회원가입)

이번 범위는 **로그인**과 **회원가입** 두 화면입니다. 예약/문의 등 다른 도메인 화면은 건드리지 않습니다.

## 1. 라우트와 파일

| 경로       | 화면        | 구현                              | 인증 |
| ---------- | ----------- | --------------------------------- | ---- |
| `/login`   | 로그인      | `src/features/auth/LoginPage.tsx`  | 불필요 |
| `/signup`  | 회원가입    | `src/features/auth/SignupPage.tsx` | 불필요 |

공통 모듈은 `src/features/auth` 안에 둡니다.

| 파일             | 역할                                                        |
| ---------------- | ----------------------------------------------------------- |
| `api.ts`         | `/api/auth/*`, `/api/users/me` 호출, `AuthApiError`, 로그인/로그아웃 흐름 |
| `session.ts`     | access token·회원 정보 보관, 로그인 후 복귀 경로(`return_path`)  |
| `useSession.ts`  | 세션 구독 훅 (헤더·화면이 로그인 상태를 함께 본다)              |
| `validation.ts`  | 서버 Bean Validation과 같은 기준의 입력 검증                    |
| `FormField.tsx`  | 라벨 + 입력 + 에러/도움말 (aria-invalid, aria-describedby)      |
| `AuthLayout.tsx` | 두 화면이 공유하는 폼 카드 레이아웃                             |

기존 `DevLoginPage`(개발용 인증 상태 전환)는 `/__dev/login`으로 옮겨 두었고, 실제 로그인 화면이 `/login`을 사용합니다.

## 2. 요청별 뷰 설계

### 2.1 회원가입 — `POST /api/auth/signup`

요청 `{ email, password, name, phoneNumber }` · 응답 `201 { email }`

| 상태          | 화면                                                             |
| ------------- | ---------------------------------------------------------------- |
| 입력          | 이메일 / 비밀번호 / 비밀번호 확인 / 이름 / 전화번호 5개 필드      |
| 제출 중       | 버튼 문구 `가입 중…`, 버튼 비활성화                                |
| 성공(201)     | "회원가입 완료" 패널 + 생성된 이메일 표시 + `로그인하러 가기` 버튼 |
| 실패          | 아래 3절의 에러 매핑에 따라 필드 아래 또는 폼 하단에 표시          |

`비밀번호 확인`은 화면 전용 필드라 요청 바디에 포함하지 않습니다. 성공 후에는 `/login?email=<가입한 이메일>`로 이동해 이메일이 채워진 상태로 로그인할 수 있습니다.

### 2.2 로그인 — `POST /api/auth/login` → `GET /api/users/me`

요청 `{ email, password }` · 응답 `200 { accessToken }`

| 상태          | 화면                                                                     |
| ------------- | ------------------------------------------------------------------------ |
| 입력          | 이메일 / 비밀번호 2개 필드, 하단에 회원가입 링크                           |
| 제출 중       | 버튼 문구 `로그인 중…`, 버튼 비활성화                                      |
| 성공(200)     | 토큰 보관 → 그 토큰으로 `/api/users/me` 조회 → 이메일·이름·연락처·권한 표시 |
| 실패(401)     | 폼 상단 `이메일 또는 비밀번호가 일치하지 않습니다.`                        |

성공 화면은 **DB에서 확인된 회원 정보**를 그대로 보여 주는 자리입니다. 토큰만 받고 끝내지 않고 보호된 API를 한 번 호출해, 발급된 토큰이 실제로 통하는지까지 한 화면에서 확인합니다. `이어서 이용하기`를 누르면 `return_path`(예: 예약 확정 화면에서 401을 만나 넘어온 경로) 또는 홈으로 이동합니다.

내 정보 조회만 실패하면 로그인 자체는 성공으로 두고 안내 문구만 덧붙입니다.

### 2.3 로그아웃 — `POST /api/auth/logout`

헤더의 `LOGOUT`에서 호출합니다. 서버는 상태를 저장하지 않으므로, 호출 결과와 관계없이 클라이언트의 토큰을 지우면 로그아웃이 끝납니다.

## 3. 에러 → 화면 매핑

| HTTP | code                  | 화면 처리                                        |
| ---- | --------------------- | ------------------------------------------------ |
| 400  | `INVALID_INPUT`       | 메시지(`필드명: 사유`)를 잘라 해당 필드 아래 표시 |
| 401  | `INVALID_CREDENTIALS` | 폼 상단 공통 안내 (어느 쪽이 틀렸는지 구분 안 함) |
| 409  | `DUPLICATE_EMAIL`     | 이메일 필드 아래 `이미 가입된 이메일입니다.`      |
| 500  | `INTERNAL_ERROR`      | 폼 상단에 서버 메시지 그대로                      |
| —    | `NETWORK_ERROR`       | `API 서버에 연결할 수 없습니다…` (백엔드 미기동)  |

서버는 검증 실패를 `"email: 올바른 이메일 형식이 아닙니다., password: 비밀번호는 필수 입력값입니다."` 한 문장으로 내려 줍니다. `api.ts`의 `parseFieldErrors`가 필드명 기준으로 나눠 각 입력 아래에 붙입니다.

## 4. 입력 검증 규칙

제출 전 프런트에서 먼저 확인하고, 최종 판단은 서버 응답을 따릅니다. 검증 시점은 **필드에서 포커스가 빠질 때**와 **제출할 때**이며, 이미 에러가 떠 있는 필드만 타이핑 중에 다시 검사합니다.

| 필드             | 프런트 규칙                    | 서버 제약                            |
| ---------------- | ------------------------------ | ------------------------------------ |
| `email`          | 필수, 이메일 형식              | `@NotBlank @Email`                   |
| `password`(로그인) | 필수                          | `@NotBlank`                          |
| `password`(가입) | 필수, 8자 이상, 영문+숫자 포함  | `@NotBlank` (길이 정책은 화면 기준)  |
| `passwordConfirm`| 비밀번호와 일치                 | 화면 전용 필드                       |
| `name`           | 필수, 50자 이내                | `@NotBlank`, `users.name` 길이 50    |
| `phoneNumber`    | 필수, `010-1234-5678` 형식     | `@Pattern(^\d{3}-\d{3,4}-\d{4}$)`    |

전화번호는 숫자만 입력해도 하이픈이 자동으로 붙습니다. 이메일은 앞뒤 공백을 제거해 보내며, 서버가 소문자로 정규화해 저장/조회합니다.

## 5. 세션 정책

- 백엔드는 refresh token 없이 access token(JWT, 기본 2시간)만 발급합니다.
- 토큰은 `localStorage['msds.auth.token']`, 회원 정보는 `msds.auth.user`에 보관합니다.
- 인증이 필요한 요청에는 `Authorization: Bearer <token>` 헤더를 붙입니다.
- 헤더(`AppLayout`)는 세션이 있으면 이름과 `MY RESERVATION`, `LOGOUT`을, 없으면 `LOGIN`을 보여 줍니다.
- 개발 모드에서는 로그인/로그아웃 시 DEV 도구의 인증 상태(`guest`/`member`)도 함께 맞춰, 기존 예약 화면의 목 응답과 어긋나지 않게 합니다.

## 6. 백엔드 연결

Vite dev 서버가 `/api` 요청을 Spring 서버로 프록시하므로 브라우저에서는 같은 오리진처럼 보이고, 별도 CORS 설정이 필요 없습니다.

```
브라우저 → http://localhost:5173/api/auth/login → (vite proxy) → http://localhost:8080/api/auth/login
```

프록시 대상은 `.env.development`의 `VITE_API_PROXY_TARGET`으로 바꿉니다. 배포처럼 API 오리진이 다른 경우에는 `VITE_API_BASE_URL`을 지정하면 그 주소로 직접 호출합니다(이 경우 서버 쪽 CORS 허용이 필요합니다).

실행 순서:

```sh
# 1) 백엔드 (msds-spring-be) — DB_URL/DB_USERNAME/DB_PASSWORD/JWT_SECRET 필요
./gradlew bootRun

# 2) 프런트엔드 (msds-react-fe)
npm install
npm run dev
```

## 7. 폼 입력 확인 시나리오

로그인/회원가입 화면에서 손으로 확인하는 항목입니다.

| # | 입력                                        | 기대 결과                                            |
| - | ------------------------------------------- | ---------------------------------------------------- |
| 1 | 빈 값으로 제출                              | 필수 필드마다 안내 문구, 요청은 나가지 않음           |
| 2 | `guest@` 같은 잘못된 이메일                 | `올바른 이메일 형식이 아닙니다.`                      |
| 3 | 가입 비밀번호 `1234`                        | `비밀번호는 8자 이상이어야 합니다.`                   |
| 4 | 비밀번호와 확인값 불일치                    | `비밀번호가 일치하지 않습니다.`                       |
| 5 | 전화번호 `01012345678` 입력                 | `010-1234-5678`로 자동 정리                           |
| 6 | 정상 값으로 회원가입                        | 201 → 완료 패널 → 로그인 화면에 이메일 채워짐         |
| 7 | 같은 이메일로 다시 가입                     | 409 → 이메일 필드에 `이미 가입된 이메일입니다.`       |
| 8 | 가입한 계정으로 로그인                      | 200 → 회원 정보 패널, 헤더에 이름과 `LOGOUT` 표시     |
| 9 | 비밀번호를 틀리게 입력                      | 401 → 폼 상단 공통 안내                               |
| 10 | 백엔드를 끄고 로그인 시도                  | `API 서버에 연결할 수 없습니다…`                      |
